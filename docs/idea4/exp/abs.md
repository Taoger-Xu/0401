# Idea4 覆盖比例 $p$ 消融实验

## 实验设置

本实验研究 Idea4（Anchor-Cover）中覆盖池比例 $p$（实现中为 `IDEA_RHO`）对性能的影响。视觉 token 总预算固定为 $K=128$，覆盖池获得
$\lceil p(K-1)\rceil$ 个 patch token，其余预算分配给全局冗余感知显著池。除 $p$ 外，其余超参数保持不变：冗余权重
$\lambda=0.5$、`cover_factor=3.0`。在 $p\in\{0.1,0.2,\ldots,1.0\}$ 上评测 GQA、MMStar、OCRBench 和
TextVQA。所有结果均为 Qwen2.5-VL-7B 在同一评测协议下的分数（%）。

## 实验结果

| $p$ | GQA | MMStar | OCRBench | TextVQA |
|---:|---:|---:|---:|---:|
| 0.1 | 56.81 | 54.87 | 57.90 | 64.10 |
| 0.2 | 56.92 | **55.58** | **58.50** | **64.18** |
| 0.3 | 56.91 | 55.38 | 57.90 | 63.99 |
| 0.4 | 56.94 | 54.78 | 57.40 | 63.08 |
| 0.5 | 56.65 | 55.24 | 58.00 | 63.22 |
| 0.6 | 56.93 | 55.19 | 58.20 | 63.35 |
| 0.7 | **56.95** | 55.29 | 58.00 | 62.36 |
| 0.8 | 56.57 | 55.31 | 57.90 | 62.27 |
| 0.9 | 56.79 | 54.99 | 57.40 | 61.59 |
| 1.0 | 56.37 | **56.12** | 57.00 | 59.29 |

> 粗体表示对应任务的最高分。MMStar 使用官方 `average` 指标，而不是某个子类别分数。

## 结果分析

- **GQA 对 $p$ 较不敏感。** 在 $p=0.1\sim0.7$ 时，分数仅在 56.65–56.95 之间波动；最高分出现在
  $p=0.7$，但相对 $p=0.2$ 仅提高 0.03 分。继续增大至 $p=1.0$ 后下降至 56.37，说明完全使用覆盖池会略微损失显著性证据。
- **MMStar 更受益于空间覆盖。** $p=1.0$ 取得最高分 56.12，说明全局与细粒度感知任务可从更充分的空间铺展中获益。
  不过其余比例并非严格单调，$p=0.2$ 也取得了较强的 55.58。
- **OCRBench 偏好较小的覆盖池。** 最优点为 $p=0.2$（58.50）。当 $p$ 继续增加时总体缓慢下降，$p=1.0$
  降至 57.00。这表明文字证据通常空间聚集，过多覆盖 token 会挤占相邻文字 patch 所需的显著池预算。
- **TextVQA 对大 $p$ 最敏感。** $p=0.2$ 取得最高分 64.18；随后分数总体随 $p$ 增大而下降，$p=1.0$ 仅为
  59.29，相差 4.89 分。这进一步支持文字任务需要保留空间聚集的高显著性 token，而不是追求均匀覆盖。

## 结论

综合四项任务，推荐将 **$p=0.2$** 作为 $K=128$ 下的默认配置：它同时取得 MMStar 55.58、OCRBench 58.50 和
TextVQA 64.18，并且 GQA 56.92 与该任务最优值仅差 0.03。若部署目标明确偏向 MMStar，可将 $p$ 提高到 1.0；若包含文字理解任务，
则不建议使用较大的覆盖比例。
